# Elysium 接管第一阶段：旧项目保护设计

## 目标

在不停止线上服务、不切换域名的前提下，保存 Blue Album 当前未提交的首页成果，并为服务器上的网站、代码、数据库、配置、服务定义、CouchDB 和校验值建立可恢复快照。

## 边界

- 允许：在本地 Blue Album `dev` 分支提交并推送当前已有改动；在服务器创建只读备份快照；读取服务状态、文件清单和校验值。
- 不允许：停止或重启线上服务；修改 Nginx、DNS、证书、数据库内容、CouchDB 内容或 Obsidian 客户端配置；把密钥、数据库文件或私人用户数据提交到 Git。
- 归档附件只保留不含密钥、数据库和私人数据的服务器网站快照；完整恢复快照留在受控服务器备份目录。

## 执行顺序

1. 检查 Blue Album 当前差异，运行与首页相关的单元测试和构建。
2. 只提交当前首页成果、测试、素材和说明文件，推送到现有 `dev` 分支。
3. 在服务器创建带时间戳的快照目录，保存代码版本、网站发布目录、数据库逻辑导出、配置脱敏副本、服务定义、Nginx 配置、CouchDB 备份信息和 SHA-256 清单。
4. 对快照压缩包再次计算校验值，并检查压缩包可以列出和解包关键文件。
5. 记录 Git 提交、快照路径、大小、校验值和未纳入归档附件的敏感内容类型。

## 回滚

本阶段不进行线上切换，因此无需恢复线上状态。若后续迁移失败，使用服务器完整快照恢复旧程序、配置和数据；新域名切换之前不删除旧目录或旧服务。

## 验收

- Blue Album 工作树干净，`dev` 分支远程提交与本地一致。
- 首页相关测试和构建均返回成功。
- 服务器快照存在、压缩包可读、校验值可复核。
- 快照中没有明文密钥、数据库转储或私人上传内容进入 Git 归档附件。
- 线上服务状态和访问地址与执行前一致。
