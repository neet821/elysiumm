# 房间分享与听歌体验设计

## 目标

移除观影房/听歌房对用户可见的房间号和用户编号，统一使用当前页面完整 URL 作为分享链接；同时修复听歌房新房间残留播放、点歌切换卡顿和搜索输入误拦截，并展示房间听歌历史。

## 方案

- 房间列表卡片和房间页使用 `window.location.origin + pathname + search` 生成分享 URL，复制按钮调用 Clipboard API，失败时使用隐藏 textarea 回退；不再渲染 `room_code`。
- `/rooms` 入口顺序调整为观影房、听歌房；听歌房移除 Mineradio 品牌同步文案，保留播放器本身的必要版权/来源信息。
- 听歌房进入和房间切换时，先清空 iframe 播放器，再将新的权威队列快照注入；选择歌曲时避免等待不必要的完整播放器重载，修正 bridge 的音频切换顺序，保证旧音频停止后新音频立即开始。
- 复用已有 `MusicRoomEvent` 历史接口和 websocket 事件，前端将播放、点歌、切歌等记录按时间倒序展示；后端只返回已脱敏的公开摘要。
- 搜索框允许空格输入；提交/搜索时仅清理首尾空白，不丢弃词间空格。
- 房间相关按钮使用不透明高对比背景、边框和文字，兼容明暗主题。

## 验收

- 前端单元测试覆盖分享复制、房间入口顺序、空格搜索、播放器清空/切歌无等待和历史渲染。
- 后端测试覆盖音乐历史访问与排序（沿用现有历史安全测试并补充播放记录）。
- 运行前端测试、后端测试、构建和 `git diff --check`；部署后检查生产健康接口及房间页面 DOM 文案。
