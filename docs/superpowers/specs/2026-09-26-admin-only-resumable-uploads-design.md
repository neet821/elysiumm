# Elysium 管理员专属可续传上传设计

## 决策与范围

用户选择完整方案 A：Uppy + tusd 独立 sidecar，由 systemd 管理并只监听本机。上传权限仅授予已认证管理员。访客不能创建、续传、取消或完成任何上传。

公开中转分享继续允许查看文件列表和下载；分享令牌不再是上传凭据。当前 `PUT /api/transfers/{token}` 旧入口必须要求管理员身份，不能因旧客户端或兼容性继续允许匿名写入。管理员页面保留中转分享和文件管理能力，并增加私有管理员文件上传/列表入口。

不修改公开内容同步协议、数据库既有表和历史迁移，不改变现有下载 URL、Range 行为、分享读取权限和令牌轮换结果。生产部署依旧走现有 CI、CD、production Environment 人工审批、发布事务与回滚，不在本次直接部署。

## 组件与边界

### 浏览器与网站 API

- 管理员文件页按需加载 `@uppy/core` 与 `@uppy/tus` 6.0.0；依赖锁文件固定解析结果，继续使用现有 Elysium 页面、认证和样式，不引入 Uppy Dashboard。
- 上传 API 放在管理员路由命名空间下。FastAPI 对 tus 的创建、HEAD、PATCH、DELETE 等每个客户端请求重新验证当前管理员身份，并验证上传记录的发起管理员、用途、目标及有效期。
- 客户端只访问同源 `/api/admin/tus/...`。Uppy 使用当前网站 Bearer 身份；平台 Cookie、服务端文件路径和 tusd 地址不得返回给浏览器。
- 服务端用途仅允许 `admin_file` 与 `transfer_file`。中转上传绑定管理员已有的内部 TransferSession ID；公共 token 只继续用于读取/下载。

### tusd 与持久状态

- tusd 作为独立的 `elysiumm-tusd.service`，由 systemd 启停；监听 `127.0.0.1` 的专用端口，不暴露公网端口。只有 FastAPI 代理能访问它。
- tusd 固定为 v2.10.0 Linux amd64 发布包 `tusd_linux_amd64.tar.gz`，SHA-256 为 `68bd62773a494c621b2b806dfaa03a57aac44044c9757440a17765283fbd7a68`；随同一 CI run 的发布材料进入对应不可变 backend release，CD 将其纳入现有部署 payload。版本二进制不提交到 Git。
- tusd 上传暂存目录位于 release symlink 之外的私有共享目录，以便 backend 切换、进程重启和回滚后仍能续传；目录权限限制为服务账号。
- CD 在切换 backend release 后按顺序安装/启用并重启 tusd，再重启 backend；tusd 或 backend 健康检查失败时，两者和 backend symlink 一起回滚到部署前版本。回滚数据目录不随 release 删除。
- 本地预览脚本可通过可配置的 tusd 可执行文件启动 loopback 子进程，纳入现有清理；没有配置 tusd 时明确报告该功能不可用，不影响其他预览功能。

## 数据和上传生命周期

新增一张只记录上传预留/状态的 `TusUploadReservation` 表；采用新 Alembic revision，不改写旧迁移或既有表。字段至少包括 tus upload ID、发起管理员 ID、用途、目标记录/中转 session ID、文件名和声明类型、声明长度、状态、创建/最后活动/过期时间、最终文件记录 ID及幂等完成标记。upload ID 唯一。

流程：

1. **创建**：FastAPI 校验管理员、用途、目标和文件元数据；在转发 tusd 创建请求前原子预留配额。配额按现有约束计算：私有管理员文件单文件上限沿用当前配置；中转文件单文件及会话上限沿用 2 GiB 规则。并发活动预留必须计入，而不能只检查已完成字节数。
2. **续传**：每次 HEAD/PATCH 都验证管理员身份、发起人、upload ID、reservation 状态和过期时间。权限失效返回明确 401/403；不得因知道 tus URL 或分享 token 绕过授权。普通断线不释放预留，管理员重新登录后可继续。
3. **完成**：只在 tusd 报告完整长度后进入验证。文件仍在私有暂存区；后端复用现有文件名、扩展名、内容类型、魔数、大小和磁盘余量检查，然后原子移入目标私有目录并在数据库写入 `AdminFile` 或 `TransferFile`。中转完成只在成功提交后更新会话总量、刷新过期时间并轮换分享 token。
4. **幂等性**：完成动作以 tus upload ID 唯一约束；重复完成/回调返回同一个最终结果，不重复建文件记录、重复计量或重复轮换 token。DB 或文件操作部分失败时清理不完整成品，reservation 可安全重试或标记失败，不能留下可公开访问的幽灵文件。
5. **取消/过期**：管理员 DELETE/cancel 先验证身份，再删除 tus 暂存并释放预留；重复取消幂等。后台周期清理超过 24 小时未活动的 reservation/tusd 暂存，清理失败保留可诊断状态并重试。普通页面关闭/网络断开不等同取消。

## 兼容与安全

- 既有 `POST /api/admin/files/upload` 可在新流程验证稳定前保留为管理员专用兼容 API；不得匿名访问。新 UI 使用 tus；旧 API 的移除须以后续消费者证据和回归验证为依据。
- 既有 `PUT /api/transfers/{token}` 保持路径，但立即增加管理员认证并应用同一预留配额约束；公开 GET、文件列表、下载与 Range 不变。验证新 tus 后可移除网页端旧 PUT 调用，但是否移除服务端兼容路径必须单独审查消费者。
- 访客分享页不显示上传组件，任何访客写请求均应被拒绝。管理员中转 UI 的 token 轮换、重载后的当前分享链接和下载行为保持原合同。
- Nginx 新增管理员 tus 流式代理参数：关闭 request buffering，设置适配分块传输的 body/read/send 超时与头部转发；不能配置成直接暴露 tusd。
- 不把客户端文件名、用途或目标 ID当作授权证据；不在日志记录 Bearer token、分享 token 或文件内容。

## 验收

### 后端与协议

- 未登录与普通账户对 tus POST、HEAD、PATCH、DELETE 均拒绝；管理员可完成创建、分块上传、HEAD 检查和取消。过期/非发起管理员不能续传。
- 实际运行固定版本 tusd 的端到端测试：上传中断、tusd/backend 进程重启后续传；完整提交及重复完成只产生一个最终记录。
- 覆盖私有文件类型校验、空文件/过大文件、配额并发竞态、过期清理、磁盘不足、失败回滚与取消释放配额。
- 普通用户和匿名访客对旧 transfer PUT 均拒绝；管理员旧 PUT 兼容测试通过；公开列表/下载和 Range 仍符合原合同。
- 数据库迁移在空库和现有库都通过；既有表结构/数据不变，新 reservation 迁移可回滚而不删除上传文件或既有数据。

### 前端与部署

- 仅管理员页面加载 Uppy；访客分享页没有上传入口。检查续传进度、暂停/取消、令牌过期提示、重新登录后恢复以及中转 token 轮换。
- 构建检查确认 Uppy 依赖按需分块；已有首屏预算不放宽。
- CI 固定 tusd 版本和校验和；CD 仅从对应 CI run 下载材料，部署测试证明 backend/tusd 同步启停及失败回滚顺序。
- Nginx/systemd 配置静态测试证明 tusd 仅 loopback 监听且未建立公网直连。
- 运行完整本地发布门禁，之后启动本地预览供用户人工验收；本轮不推送、不合并、不生产部署。

## 明确不做

- 不允许访客/持链接用户上传。
- 不迁移公开同步客户端、头像、视频、直播录像、聊天附件或其他已有上传流程。
- 不引入 Docker、额外用户身份服务或新的公网上传域名。
- 不删除现有文件、传输会话数据、下载兼容路径或历史迁移。
