# 房间实时同步协议

房间播放状态以服务端快照为准。快照包含媒体 ID、播放版本、位置、速率和服务端时间；控制、结束事件及视频队列变更继续校验版本。媒体队列仍由逐项增删、移动和选择操作修改，不接受客户端整份快照覆盖服务端队列。

## 实时操作防重放

当前网页客户端为每个页面运行时生成 `client_instance_id`，并为 `playback_control`、`time_heartbeat`、`video_ended` 和 `music_ended` 按发送顺序递增 `operation_seq`。页面运行期间 Socket.IO 断线重连会继续使用同一实例与序号；完整刷新会生成新实例。

服务端按用户、房间和客户端实例记录最近接收的序号。相同序号视为重试并幂等忽略；较小序号被拒绝并返回权威播放快照。记录仅驻留单个后端进程，最多保留 20,000 个实例键，并在 24 小时不活动后过期。因此生产仍须保持单 worker；如需多 worker，先为该 guard 增加共享存储或 Socket.IO message manager。

扩展字段是兼容可选项：旧客户端未发送实例和序号时保留原行为；只发送其中一个或发送无效值会被拒绝。新视频播放控制与心跳同时携带当前 `media_id`，服务端检查它仍是房间当前媒体，避免旧媒体上的迟到控制操作影响新视频。

## 时钟估计与重连

已加入房间的网页客户端连接后，以及连接期间每 30 秒发送一次 `clock_probe`。服务端只向已认证房间成员回送客户端原始发送时间、服务端接收和发送时间。客户端据此扣除服务端处理时间计算往返时延与时钟偏差，并使用最近八个样本中往返时延最低者；尚无探测样本时继续使用既有快照到达时间估计。

断线重连后客户端重新加入房间、接收权威快照，再开始时钟探测；页面从后台恢复时也继续请求快照。客户端不发送或持久化播放权威状态。此扩展不改 Socket.IO 既有播放快照字段、数据库表或迁移历史。
