# 单直播间使用与运维

## OBS 开播

管理员先进入“账户 → 管理员控制台 → 直播”，点击“更换推流密钥”。完整密钥只显示一次，请立即保存，不要截图或转发到公开群。

OBS 设置如下：

- 服务：`自定义`
- 服务器：使用管理员页显示的地址，当前为 `rtmp://8.148.83.28:1935/live`
- 推流密钥：使用管理员页一次性显示的完整内容，格式为 `stream?token=...`
- 视频编码：H.264
- 音频编码：AAC
- 关键帧间隔：2 秒
- 建议起步：1920×1080、30 fps、4–6 Mbps；服务器不转码，观众收到的就是 OBS 输出规格

开始推流后约数秒，管理员页会显示直播状态和画面规格。观看地址为 `/live`，目标延迟约 5–10 秒。OBS 短暂断开 30 秒内恢复会继续计入同一场；超过宽限期后页面显示“直播已结束”。

## 观看权限

管理员可随时切换三种模式：

- 公开观看：任何拿到网站地址的人都可观看。
- 仅指定用户：访客必须登录，并且账号已加入“开放用户”。
- 仅邀请链接：管理员创建带有效期的私密链接，访客无需登录。邀请原文交换成功后会从浏览器地址栏清除。

停用邀请后，已打开页面的后续媒体请求也会被拒绝。关闭“允许访客观看”会立即暂停所有普通访客；管理员仍可检查直播状态。

## 访客信息与隐私

每次观看会记录 IP 地址、本地解析出的国家/地区/城市、设备类型、操作系统、浏览器、首次与最后出现时间以及累计观看时长。地区查询只读取服务器上的本地城市库，不把 IP 发给第三方。记录默认保留 90 天，管理员可提前清除。

网站应在隐私说明中告知上述处理目的和期限。邀请链接相当于临时门票，不应公开发布；管理员界面不会再次显示完整邀请或推流密钥。

## 自动录像

录像保存在 `/srv/blue-album/live/recordings`，不放在 Git 仓库中。每段完成后会计算摘要并出现在管理员页面，可直接播放、下载、改名或删除。磁盘剩余空间接近 5 GiB 保留线时，系统只暂停新录像，不中断直播。

录像不会自动公开，也不会自动删除。未来接入网盘时，以数据库中的 `remote_provider` 和 `remote_file_id` 为边界增加后台上传器；本地录像在远端确认完整之前不得删除。

## 服务和端口

- 公网只需开放 TCP 1935，供 OBS 推流。
- 8000、8888、9996、9997 只允许本机访问；网页媒体统一经过 Nginx 的 `/live-media/`，每个请求都会检查观看授权。
- 阿里云安全组和主机防火墙都需要允许 TCP 1935。
- 当前直接 IP、纯 HTTP 部署必须设置 `LIVE_COOKIE_SECURE=0` 才能观看；一旦配置 HTTPS，应立即改回 `1`。纯 HTTP 无法保护邀请链接和观看 Cookie 在传输途中不被窃听。

安装前先运行：

```bash
scripts/provision-live-streaming.sh --check
```

安装时先完成生产备份，再运行 `sudo scripts/provision-live-streaming.sh --install`，把 `/etc/nginx/snippets/blue-album-live.conf` 包含进现有 Blue Album 站点，执行 `nginx -t` 后再重载。后端运行环境必须同时包含 `backend/prod.env.example` 中的全部 `LIVE_*` 项。

## 故障处理

- 推流被拒绝：在管理员页更换密钥，将新密钥完整粘贴进 OBS；旧密钥立即失效。
- 需要立即停播：点击“强制断流”，然后停止 OBS；若 OBS 自动重连且密钥仍有效，它可能再次接入。
- 画面规格异常：确认 OBS 输出为 H.264 + AAC，关键帧 2 秒，不要使用 AV1、HEVC 或仅视频输出。
- 网页无画面：依次检查网站健康、`blue-album-mediamtx` 状态、本机 HLS、Nginx 授权路径和 1935 监听。
- 磁盘不足：下载或迁移旧录像后在管理员页删除；空间恢复到保留线以上时录像会自动恢复。
- 媒体服务重启：`systemctl restart blue-album-mediamtx`。重启不会删除已完成录像，但当前观看会短暂重连。

本功能不包含服务器转码、多码率自适应、向第三方平台转推或自动公开录像。
